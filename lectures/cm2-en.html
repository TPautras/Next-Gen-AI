Opening

The real problem: cheap models, answers we can trust

  • The goal: answer hard questions with cheap models, and still give true answers.
  • Why cheap: a top model costs about 100 times more per token (Lecture 1, slide 5).
  • The risk: a cheap model is wrong more often, and a wrong figure looks like a right one.

A real case. A data company sends revenue figures to online shops. A customer compares them with the figures of another tool. The two numbers differ. The customer stops trusting the company, and leaves.

Today's method: comparable answers → quorum → checks → routing.

Check: a test on an answer, before we deliver it. It compares the answer with something the model did not write: the format, an exact query, or a fresh read of the source. In real life: code or an agent runs it on every answer; a person only reviews samples, later. If the check fails, the answer is not delivered. This afternoon: you are the check, by hand, with your reference values.

Opening

Quorum: the definition

Quorum: the minimum number of models that must give the same answer before we accept it. We write it k of n.

  • n: the number of models that we ask. This group of models is the panel.
  • k: the threshold. With a 3-of-5 quorum, 3 models out of 5 must agree.
  • Abstention: no answer reaches k, so the system says "I do not know".
  • Family: the models of one maker. A panel mixes families.

42 has 3 votes: a 3-of-5 quorum accepts it. In production I used 11 models; this afternoon you use 3, then 5.

Comparing

The solution: an imposed output format

1. The prompt imposes one JSON format, with the value and everything needed to read it:

{"value": 1250, "unit": "cent", "currency": "EUR", "tax": "excluded", "date": "2026-11-18"}
  • 2. Code, not a model, checks every field.
  • 3. Code converts every answer to one form: an integer, in cents.
  • 4. Only then, the vote.

Rule: if a field is missing, the answer is rejected and does not vote. We never guess a unit. A missing value is not a zero.

JSON: a text format made of names and values. This afternoon: the kit already imposes one integer, in euro cents, excluding tax.

What is a resource?

  • Resource: one model, reached through one route (Lecture 1, slide 11).
  • Level: the capability that a question needs: level 1 simple, level 3 hard. A resource has a level too, measured on tests.

Three selection rules

RuleWhat happens for a level 3 question
A. Always the cheapestit takes R1: cheap, and not good enough
B. Always the same top modelblocked when its quota is exhausted, and too expensive for easy questions
C. Filter, then the cheapest that is good enoughright level, lowest price

Rule C can find nothing. Then the system waits or abstains, and says why. It never goes back to R1 in silence.

Routing

When a call fails: the retry policy

Policy: the written rules that the code applies, with a version number. Attempt: one call to one resource.

A realistic policy. At most 10 attempts on the same resource. 1 minute of waiting between two attempts. Then the next resource that is good enough. If there is none: defer or abstain. Never deliver without the required check.

  • A busy provider answers HTTP 429 for a few minutes: you saw it in TD 1.
  • A hard question can take 10 minutes to answer: a limit of 10 seconds kills good answers.
  • Every attempt is one line in the trace (column attempts).
  • A stronger model is one more attempt. It is not a proof.
Routing

A new model arrives: we test it

What we know about model ZWhat it proves
Z answers our callsit is available, nothing more
Its name, its size, its public index (Lecture 1, slide 13)a description, not a result on our questions
No test on our questions yetcapability unknown: not good, not bad

So we test it, on real questions:

  1. Z receives the real questions, next to the panel.
  2. Its answer is logged. It does not vote: this is a shadow test.
  3. Code compares Z with the accepted answers and with checked samples.
  4. If Z holds, it joins the panel. If not, it leaves.
Routing

Testing under quota pressure

  • The real limit is time. While the quotas last, nobody stops to test: the team moves fast with the models that it knows.
  • Tests happen when a quota is exhausted, and a new model is the only one left.
  • So we take the risk where an error is cheap.
Use, as in your routing ruleWith a new model

When the answer is a text

A real case. Canada, February 2024: the chatbot of Air Canada told a customer that he could ask for a refund after his purchase. The real policy said no. A tribunal decided that the airline must pay.

Two models never write the same sentence: we cannot count identical texts as we count integers.

Source"Delivery is expected on Tuesday."
Answer A"Delivery on Tuesday, with a guaranteed refund if late."
Answer B"Delivery is expected on Tuesday."

Step 1: split each answer into claims, short statements that can each be checked. A makes three claims: Tuesday; it is certain; a refund is guaranteed.

Who splits? A model call with one instruction, or code when the answer is JSON: one field, one claim.

Judging

The rubric: four questions

Judge: a model that receives the source, an answer and the criteria, and gives a verdict for each claim. Rubric: the list of criteria. Modality: how sure a sentence is: possible, expected, certain, required.

A fails, with two changes: one addition, one change of modality. B passes on this source.

Judging

The judge inside the quorum

answer→claims→3 judge models, 3 families→one verdict per claim and per judge→quorum 2 of 3 on each claim

Verdicts: supported, not supported, undetermined. The answer passes only if every claim is supported.

Check the judge:

  • Show A then B, then B then A, with the same source: if its choice follows the position, the judge has an order effect.
  • Run it on cases already marked once by a person: 47 right out of 50 is fine; much less, we do not use it.
  • Include a case where the right verdict is "undetermined".

The solution: vote on the whole answer

  1. Code writes each answer in one normal form: same field order, same units.
  2. Code computes a hash of the whole answer: a short fingerprint. Same answer, same hash.
  3. The vote counts the hashes, not the fields.

Three different hashes: no majority. The quorum abstains. This is the right decision.

If model A receives the first line and model B the second, their answers differ. This says nothing about the models.

To compare two models, we give them the same information, and we store what each one received.

Reserve B

"I do not know yet" is an answer

Question: how many units are available now? Source: the stock at 9:00:00, and no list of movements.

A good answer

"The last reading shows 8 units at 9:00:00. The current stock cannot be given with this data."

  • It keeps the useful fact, with its time.
  • It does not turn "unknown" into zero, and it does not present old stock as current.
  • To finish the job: ask for the movements after 9:00:00.
